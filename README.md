# 镇主传说 · Town Legend

一款运行在浏览器中的 2D 像素风卡牌放置游戏。玩家扮演城镇领主，通过购买并部署卡牌来管理经济链（战斗 → 制造 → 商店），同时应对不断涌现的怪物威胁，推动城镇持续升级。

## 技术架构

| 层 | 技术 |
|---|---|
| 游戏引擎 | Phaser 3（WebGL / Canvas，像素渲染，antialias 关闭）|
| 语言 | TypeScript |
| 构建工具 | Vite |
| 状态管理 | 自研响应式 `GameStore`（发布/订阅模式）|
| UI 层 | 原生 DOM（卡牌面板、HUD、弹窗覆盖在 canvas 之上）|
| 像素图形 | 纯代码绘制：`Phaser.GameObjects.Graphics` → `generateTexture` |
| 存档 | `localStorage`（JSON 序列化，版本号 `2`）|

源码结构：

```
src/
├── main.ts                  # Phaser 初始化 + 布局同步
├── types.ts                 # 全局类型定义
├── data/
│   ├── cards.ts             # 所有卡牌静态定义 + 抽卡逻辑
│   └── items.ts             # 战利品 / 成品 / 配方定义
├── systems/
│   └── store.ts             # 游戏状态机（GameStore）
├── scenes/
│   └── TownScene.ts         # Phaser 场景：渲染、tick 驱动、AI、战斗
└── ui/
    └── UIController.ts      # DOM 卡牌面板、商店、库存、操作菜单
```

## 时间系统

时间**完全自动推进**，玩家无法暂停或调速。

| 单位 | tick 数 | 实际时长（约） |
|---|---|---|
| 1 tick | 1 | 125 ms |
| 1 周 | 40 tick | 5 秒 |
| 1 月 | 160 tick（4 周）| 20 秒 |

每个 tick，`TownScene.update()` 通过累加器驱动：

```
tickAccum += delta
while tickAccum >= 125ms:
    doTick()
```

每 tick 依次执行：
1. 运行实体 AI（更新移动目标、触发战斗）
2. 推进 `store.advanceTick()`（周末结算 / 月末结算）
3. 若有新日志则推送到侧边栏并刷新精灵
4. 每 24 tick 尝试生成路过行人

## 卡牌系统

### 获取卡牌

商店一次展示 **6 张**卡牌（从当前城镇等级可用卡池中随机抽取，不重复直到池耗尽）。

- 购买后该格变为「已售出」占位，**同一格不可重复购买**。
- 6 张全部售出后**自动刷新**商店。
- 手动刷新商店花费 **5 金币**。
- 商店卡池受城镇等级限制：等级 N 的城镇只能出现 ≤ N 级的卡牌（等级从 0 起算，城镇初始 1 级，可出现 0 级和 1 级卡）。

### 定价规则

同等级所有卡牌**价格相同**，功能差异不体现在价格上：

| 卡牌等级 | 购买价 | 场上维护费/月 | 手牌维护费/月（×0.5）|
|---|---|---|---|
| 0 | 20 | 5 | 2.5（向上取整）|
| 1 | 50 | 10 | 5 |
| 2 | 100 | 20 | 10 |
| 3 | 180 | 35 | 17.5（向上取整）|

> **怪物卡例外**：购买价与等级相同，但维护费永远为 0。

### 打出卡牌

从手牌打出到场上，需满足场上牌数 < 当前上限。

- **人物卡**：打出时弹出岗位选择窗口（商店 / 制造 / 战斗）。
- **怪物卡**：打出时弹出出生点选择（左侧 / 右侧 / 顶部）。
- **建筑卡、魔法卡**：直接上场，无额外选项。
- 场上的牌**不能收回到手牌**，但可参与升级。

### 升级

集齐**任意来源（手牌 + 场上）共 3 张相同 id 的卡牌**可触发升级：

- 保留第一张，销毁另外两张。
- 升级后：`level +1`，`upgrades +1`，所有数值属性 **× 1.3**（取整）。
- 同时从当前卡池随机**免费获得 1 张**卡牌加入手牌。
- 升级后仍保留在原来的位置（场上或手牌）。

### 卡牌类型

#### 人物（Human）

拥有属性：`hp / maxHp / atk / def / intellect / strength / diligence`

上场后分配**岗位**，决定其在场景中的活动区域和月末结算贡献：

| 岗位 | 关键属性 | 区域位置（画面宽度比例）|
|---|---|---|
| 商店 | 智力（intellect）| 18% |
| 制造 | 勤劳（diligence）| 36% |
| 战斗 | 力量 / atk / def | 86%（兵营）|
| 无（Idle）| — | 54%（城镇大厅）|

#### 怪物（Monster）

拥有属性：`hp / maxHp / atk / def / rarity / aggression / strength / lootId / lootQtyMin / lootQtyMax`

上场后分配**出生点**：

| 出生点 | 场景 X 坐标 |
|---|---|
| 北（left）| 画面左侧屏外（x = -60）|
| 东（east）| 画面右侧屏外（x = W + 60）|
| 南（south）| 画面正上方（x = W × 0.5）|

怪物**不需要维护费**。

#### 建筑（Building）

拥有属性：`capacity / bonus`。建筑卡目前作为卡牌存在于场上，占用场上槽位，需要支付维护费。（bonus 与 capacity 的实际效果在当前版本中尚未接入经济结算，属于设计扩展点。）

#### 魔法（Magic）

拥有属性：`effect / power`。在场时持续生效，效果类型：

| effect 标识 | 效果 | 当前 power |
|---|---|---|
| `buff_human_atk` | 全体人物攻击力 +power | 祝福：+2 |
| `buff_human_def` | 全体人物防御力 +power | 强化术：+4 |
| `debuff_monster_atk` | 全体怪物攻击力 -power | 诅咒：-2 |
| `extra_passersby` | 每月行人数 +power | 市集魔法：+5 |

魔法卡与人物卡相同，需要支付维护费。

## 场上区域与角色行为

场景从左到右划分固定区域，各区域有对应建筑贴图：

```
左屏外    商店区    制造区    城镇大厅    战斗区    兵营区    右屏外
(怪物)   18%       36%       54%        72%      86%      (怪物)
          蓝色店铺  石质工坊  红顶大厅   —        红顶兵营
```

人物在所属区域内以 ±30px 的范围随机漫步（每 tick 有 2% 概率重新选取漫步目标）。

**战斗人员**特例：
- 有怪物进攻时：脱离兵营区，主动追向最近的攻击中怪物。
- 无怪物进攻时：回到兵营区（86% 位置）休息。

怪物在出生点附近以 ±15px 范围漫步等待，倒计时归零后向城镇大厅（54%）进军。

## 战斗系统

### 侵略倒计时

怪物上场后初始化 `aggressionCountdown = aggression`（月数）。每月末减 1，归零时开始进攻并写入日志「开始进攻城镇！」

### 实时战斗（tick 级别）

当怪物 `aggressionCountdown === 0` 且处于活跃状态时，战斗人员开始追击：

1. 每 tick：战斗人员计算与所有进攻中怪物的距离，向最近的一个移动（速度 80px/tick）。
2. 当两者距离 **< 36px** 时进入攻击范围：
   - `attackCooldown` 每 tick 减 1，归零时触发一次互相攻击，然后重置为 **2**（即每 2 tick 打一次）。
3. 命中时触发火花粒子特效，并计算伤害：

```
dmgToMonster = max(1, (human.atk + buff_human_atk) - monster.def)
dmgToHuman   = max(0, (monster.atk - debuff_monster_atk) - (human.def + buff_human_def))
```

### 战斗结果

**怪物 hp ≤ 0**：
- hp 重置为 maxHp。
- `aggressionCountdown` 重置为 `aggression`（重新开始倒计时）。
- 怪物精灵飞回出生点。
- 立即随机掉落战利品（见下表）并加入玩家库存。

**人物 hp ≤ 0**：
- hp 重置为 maxHp。
- `isActive = false`，`restMonthsLeft = townLevel`（休息城镇等级数个月）。
- 人物精灵飞回城镇大厅，显示为半透明。

### 行人与战斗的关系

当有任意怪物处于进攻状态时，当月行人数归 **0**，商店本月无收入。

## 经济链

完整经济链为单向流程：

```
战斗人员击退怪物
       ↓
获得战利品（进入库存）
       ↓
制造人员每周积累勤劳点 → 满足配方条件时自动合成成品
       ↓
成品进入库存
       ↓
月末：商店人员 × 行人数 → 售出成品 → 获得金币
```

### 周结算：制造

每周末（每 40 tick）：

1. 统计所有制造岗位的活跃人物，累加其 `diligence` 值到 `craftPoints`。
2. 遍历所有配方，若 `craftPoints ≥ craftCost` 且库存中战利品满足 `inputs` 要求，则消耗材料与工时，产出成品并写入日志。

配方（当前均为 1-to-1，结构支持多输入扩展）：

| 输入战利品 | 数量 | 输出成品 | 工时（diligence 点）|
|---|---|---|---|
| 鼠皮 | 3 | 皮革 | 8 |
| 狼牙 | 2 | 武器 | 12 |
| 魔晶 | 1 | 魔法石 | 10 |
| 妖羽 | 4 | 羽毛斗篷 | 14 |
| 龙鳞 | 2 | 龙甲 | 20 |

月末时 `craftPoints` 强制重置为 0（不跨月累积）。

### 月末结算：商店收入

条件：同时满足以下三点才产生收入：
1. 有至少 1 名商店岗位的活跃人物。
2. 库存中有至少 1 件成品。
3. 当月行人数 > 0（未被怪物进攻）。

计算：
```
passersby = 5 + townLevel × 3 + getMagicBonus('extra_passersby')
sellCapacity = min(totalProducts, passersby × 2)
shopPower = sum(shopWorker.intellect)
income per item = product.sellPrice × (1 + shopPower × 0.05)
```

售出的成品从库存中扣除，金币加入总金币。若商店有人但无成品，写入提示日志。

## 月末结算流程

每月 160 tick 结束时，按以下顺序执行（执行完毕后自动存档）：

1. **税收**：`gold += LEVEL_COST[townLevel]`（当前等级卡牌的定价，即 20 / 50 / 100 / 180）
2. **怪物侵略倒计时**：每只活跃怪物 `aggressionCountdown -= 1`，归零时写入进攻日志
3. **统计当前攻击者**（供行人计算使用）
4. **商店收入**（详见上节）
5. **维护费**：
   - 场上非怪物牌：按定义维护费全额扣除
   - 手牌：按定义维护费 × 0.5 上取整扣除
   - 金币不足时：从场上**倒序**（最后上场的先罢工）标记非怪物活跃牌为罢工状态（`strikeMonthsLeft = 1`，即下月恢复），直到补足缺口
6. **恢复**：所有 `isActive = false` 的牌，`restMonthsLeft` 和 `strikeMonthsLeft` 各减 1，两者同时归零时恢复活跃
7. **城镇升级检查**：`手牌 + 场上` 中等级 ≥ 当前城镇等级的牌数量 ≥ **10** 时触发升级

## 城镇升级

升级条件：`count(cards where card.level >= townLevel) >= 10`（手牌 + 场上合计，不含已废弃）

升级效果：
- `townLevel += 1`
- 场上牌槽上限：`5 + (townLevel - 1) × 2`（初始 5，每级 +2）
- 商店自动刷新（新等级卡牌解锁）

城镇等级同时决定：
- 每月税收金额（= 当前等级卡牌定价）
- 战败人物的休息时长（= townLevel 个月）
- 商店可出现的卡牌等级上限

## 存档系统

- 存档时机：每月末结算完成后自动写入 `localStorage`，key 为 `town_legend_save`。
- 存档内容：金币、城镇等级、tick / week / month、手牌、场上、废弃牌、商店格子状态、库存、最近 50 条日志。
- 读档时机：页面加载时 `initUI()` 调用 `loadFromLocalStorage()`，若版本号匹配（version = 2）则自动恢复，并弹出通知。
- 版本不匹配时忽略旧存档，重新开始。

## 设计扩展点（已在代码中预留）

- **配方多输入**：`Recipe.inputs` 为数组结构，当前均为单元素，未来可直接扩展为多材料合成。
- **魔法 effect 标识**：字符串 key 机制，新增魔法只需新加 effect id 并在相应结算处 `getMagicBonus(effect)` 即可生效。
- **建筑 bonus / capacity**：字段已定义，当前未接入结算公式，为后续「建筑加成制造/商店效率」预留。
- **怪物出生点排列**：按场上顺序由近到远排列，支持多怪物并存各自出生点。
- **精灵差分**：人物贴图按岗位（蓝/琥珀/红）+ 升级等级（0/1/2，颜色逐级加深）生成独立纹理，扩展新岗位只需在 `sprites.ts` 新增绘制函数。
